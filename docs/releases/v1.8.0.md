# Wird 1.8.0 (formerly Daily Deeds Reminder)

A new name and logo, and the first properly signed release build. This release exists mainly to stop the Google Play Protect warning that appeared on every install.

## Why Google warned on every install
The GitHub releases up to 1.7.0 were the **debug** build: `debuggable`, application id `com.dailydeeds.reminder.debug`, signed with a machine-generated debug key. Play Protect treats that as unsafe when it comes from a browser download. From 1.8.0 the published APK is the minified **release** build signed with a dedicated key. A brand-new APK from outside the store can still trigger Play Protect's one-time "unrecognized app" prompt until the app is on Google Play or the developer is verified; see `docs/DISTRIBUTION.md`.

## Name and logo
- The app is now «ورد» (Wird). The mark is an eight-point khatam star with a crescent and a dot, in gold on emerald, matching the in-app theme.
- Adaptive launcher icon, a **themed monochrome icon** (Android 13+), and a redesigned status-bar notification icon.
- Master artwork `branding/wird-icon.svg`, generated by `branding/generate_icons.py` (also writes the 512 px Play icon and the 1024×500 feature graphic into `branding/play/`).
- The dedication line stays inside the app; it is not part of the name or the store listing.

## Release signing and verification
- Release key outside the repository, certificate SHA-256 `9B:0C:29:2B:CC:9E:1F:97:30:32:FC:B2:DF:B4:AA:9E:79:A4:16:49:86:03:88:56:C1:09:2A:9B:5C:F1:FF:36`.
- `scripts/verify_release.py` rejects a debuggable APK, the debug certificate, a missing v2/v3 signature, a wrong application id or permission, or a stale hash.
- `scripts/emulator_smoke.py` installs the APK on an emulator, tours the five tabs and fails on any crash. The minified build had never been run before; it is now run on an Android 14 emulator before release.
- CI now also builds the minified release; a tag workflow (`release.yml`) builds, signs and verifies the release from repository secrets.

## Application id changed: move your data
The application id is now `io.github.ashh1461.wird`, so Wird installs next to the old app and cannot read its data. In the old app open Settings → «البيانات والنسخ الاحتياطي» → export; in Wird import the file (the app restarts), then uninstall the old app. Voice files are not part of a backup.

## Verification
- `Wird-v1.8.0.apk`: 3,678,985 bytes, SHA-256 `c0db2309a6b73daaf484ff42abe876ad43176eb975df2b615bd01a1cf3ef5240`. 168 unit tests pass, `lintDebug` clean.
- The signed APK passes `scripts/verify_release.py`: v2 and v3 signatures verified, certificate SHA-256 equal to the one above, application id `io.github.ashh1461.wird`, not debuggable, the same nine permissions as 1.7.0, and a hash different from 1.7.0.
- Emulator smoke run (Android 14, x86_64, `scripts/emulator_smoke.py`): the **minified release build installed, launched, kept MainActivity in the foreground and logged no crash**; the Today screen rendered correctly (Hijri date, prayer times, deed list, five-tab bar). The emulator image itself was unstable on this virtual machine (its own System UI and Bluetooth processes hung and showed ANR dialogs), so the full five-tab tour screenshots and a picture of the launcher icon could not be captured. The icon artwork was checked in the rendered 512 px Play icon and the vector XML, not in a launcher.
