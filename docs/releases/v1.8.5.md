# Wird 1.8.5: privacy and supply-chain hardening (pre-release)

A security-only release. It changes no features and no texts; it hardens where the app keeps your data and how it fetches optional adhan voice packs. It installs over 1.8.x with the same signing key (version code 23), and your settings, favourites, reading positions and backups carry over unchanged.

Both items come from a static security audit of the signed 1.8.4 APK (`docs/security/2026-11-27-apk-audit.md`), which found no critical or high issues — only these two optional "defence-in-depth" improvements.

## What changed

- **Personal data now waits for your screen lock.** Since 1.8.2 all of the app's settings were kept in Android's *device-protected* storage, so prayer alarms can be restored after a restart before you first unlock the phone. That storage is encrypted with the device key rather than your screen lock, so it can be read in the short window before the first unlock. From this version the app keeps **only** what the prayer alarms actually need before unlock in that storage — the prayer and alarm settings, and the location used to compute prayer times — and moves everything else (the Khums figures, favourites, reading positions, deed progress, tasbih and make-up counters, theme and reminder times) into *credential-protected* storage, which only unlocks after you enter your screen lock. The location stays in device-protected storage on purpose, because prayer times are recalculated before the first unlock.
- **Adhan voice packs are pinned to a fixed, verified source.** The optional voice-pack catalogue was fetched from a branch that can change over time, and the checksum that protects each voice came from the same place as the catalogue. The app now fetches the catalogue from a fixed, unchangeable snapshot and checks it against a fingerprint built into the app before trusting it, so a changed or mis-published catalogue is rejected. All the existing protections stay in place: HTTPS only, a small list of allowed hosts re-checked after every redirect, strict size limits, and a per-voice checksum verified before any voice is installed.

## Compatibility

- Your settings, favourites, reading positions and backups carry over unchanged. The first time you unlock the phone after updating, the app moves your personal settings into the more protected store once, with nothing lost. Backups made by this version, and older backups restored into it, round-trip every setting exactly as before.
- No new permissions. No change to what the app sends or stores on any server (it still has no backend and no account).

## Verification

- Unit tests (new / changed):
  - which settings keys stay in device-protected storage and which move to credential-protected storage (`PrefsClassifierTest`)
  - the one-time store split runs only after the first unlock (`DirectBootTest`)
  - the store split for both the 1.8.2–1.8.4 and the pre-1.8.2 layouts, a fresh install, and a backup that round-trips across both stores (`PrefsStorageInstrumentedTest`, runs on a phone/emulator)
  - the voice catalogue is pinned to a fixed snapshot (not a branch), the shipped catalogue matches its built-in fingerprint, and a tampered catalogue is rejected (`VoiceAndPolicyTest`)
- Full unit-test run, Android lint and the debug build: see `progress.md` (328 unit tests, 0 failures; lint 0 errors).
- A separate read-only code review of the change found no blocking issues; its two minor migration notes were fixed.

## Not verified (needs a person with a phone)

1. **Install over 1.8.4:** settings, the place, favourites and reading positions are all still there after updating, and nothing is reset.
2. **Prayer alarms still fire after a restart before unlock:** set a prayer alarm, restart the phone, and leave it locked — the adhan/alarm still plays at the prayer time (this is the behaviour the device-protected store exists for, now with a smaller set of keys).
3. **Khums and other personal data survive a lock cycle:** enter some Khums figures and a favourite, lock and unlock the phone, and confirm they are intact.
4. **Backup round-trip:** export a backup, change the place, a favourite, the theme and the Khums figures, then import the backup — every value returns to the backed-up state.
5. **Voice packs still work:** open the adhan voice list and confirm it loads; if a pack is available, downloading and playing it still works.
