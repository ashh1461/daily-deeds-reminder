# v1.9.0: UI languages (Arabic, English, Persian)

Scope agreed with the owner on 2026-11-27: **UI languages only.** Quran translations and the hadith and Nahj
al-Balagha library move to v1.9.1 or later, once each source's licence is checked. Version 1.9.0, **code 24**
(v1.8.5 already used 23).

## Rules
- Arabic stays the default resource set (`res/values`). English is `values-en`, Persian `values-fa`.
- Only the app's own interface is translated. Religious text (Quran, supplications, Mafatih, Sahifa, al-Mizan,
  ziyarat) is content: never translated, never summarized, and always shown right to left (`RtlContent`).
- Existing users see no change: the language setting defaults to Arabic (`AppLanguage.DEFAULT_PREF`).
- Numbers in format strings use `%1$s` with an already formatted number, never `%d`, so a locale cannot switch
  the digits the app shows today.
- `StringResourcesTest` keeps the three files in lockstep (same keys and placeholders, nothing empty, no Arabic
  script in English).
- Persian strings are a draft and need a native speaker's check before a Latest release.

## Design (stage 0, done)
- `util/AppLanguage`: the three languages plus "follow the device" (`system`); pure, unit-tested.
- Stored in `pref_app_language`, a **boot key** (device-protected), so the locked adhan notification can be
  written in the chosen language.
- `util/LocaleSupport.localized(context)`: the app manages its language itself (works from API 26 and in direct
  boot). `MainActivity.attachBaseContext` wraps with it; changing the language recreates the activity.
- The theme takes its layout direction from the configuration (RTL for ar and fa, LTR for en) instead of forcing
  RTL. `ToolScaffold` no longer forces RTL.
- Settings has a Language section; each language is named in its own script.
